# 音声入力・チャット改善（2026-10-16）

## 採用判断

標準は **Moonshine Japanese Tiny / 非Streaming** を維持する。Baseは設定で明示的に選択可能。Baseの初期化失敗時には音声UIに「Tinyに切り替えて再試行」を表示し、利用中モデル名も表示する。自動の無通知切り替えはしない。SDKは実際に日本語Tiny/Baseを提供する `@moonshine-ai/moonshine-wasm@0.1.5` のまま。Tiny Streamingは採用していない。

同一の5本の合成音声を実際のTiny/Base重みで認識したが、Baseが優位ではなく、より大きなメモリを必要とした。小規模な合成音声であり、人の声に対する一般的な優劣を結論づけるデータではない。iPad第10世代の実機性能は未検証。Baseを無条件に標準へ昇格する根拠は得られなかった。

モデル配布量はWASMから取得したマニフェストに基づき、Tiny 71,815,430 bytes、Base 141,001,214 bytes。実重みのサイズ・CRC32C・配信元CORSを確認した。重みをGit/Pagesへ再配布していない。既存SDKのモデル保存・キャッシュ形式を維持。

## 新しい操作と責務

- 入力欄のマイクを押すとマイク許可、モデル準備、録音を自動実行。Safariの操作起点を失わないようAudioContextの生成/resumeと権限要求をタップから直接開始する。モデル準備中の音声は文字起こししない。
- コンパクトなパネルに録音状態、実測音声レベル、停止・キャンセルだけを表示。停止後は入力欄だけで結果を確認・修正し、自分で送信する。モデル名とエラー時の回復操作は表示するが、評価・技術診断は設定へ移動。
- 状態はidle/loading/recording/stopping/review/error。読み込み中もキャンセルできる。別画面には停止可能な録音表示を維持。バックグラウンド移行時は停止、pagehideはモデルWorkerとマイクを解放。
- `VoiceSession` はSDKの `SttWorkerHost` を使う。旧 `MicTranscriber` は同期推論をメインスレッドで行うため、長い推論中に操作や音声処理が詰まる可能性があった。新構成は推論とWASMをWorkerへ分離。
- 音声はAudioWorkletでmonoにまとめ、4096フレーム単位でWorkerへ渡す。SDK側が入力サンプルレートを処理する。メインスレッドの独自リサンプリングを廃止。Workletの実レベルだけを軽いCSS変形へ反映。
- 停止時はWorkletの末尾を排出し、1秒の無音を追加してからSDKのstop/ForceUpdate完了を待つ。行の初回イベント、更新、完了をIDで置き換える。未確定の末尾も保持して明示する。IDの重複で追加せず、完了順が変わっても元の行順を維持する。手動編集後は認識イベントで上書きしない。
- 録音終了は音声ストリームだけを閉じる。次の録音は同じモデルWorkerを再利用。送信時はWorkerを自動終了して通常のRuri検索へ戻る。Ruriの保存ファイルは消さない。同時常駐はiPad実測がないため採用せず、メモリ解放をWorker終了で確実にする。解放を確認できない場合は軽量検索を維持し、復旧操作を残す。
- 初期化に120秒の期限を設け、失敗・権限拒否・Workerの遅延時にも文字入力を使えるようにする。録音キャンセルはモデルWorkerを終了し、未編集なら録音前の入力へ戻す。

入力は200から2,000文字へ拡張し、会話と検索の両境界を揃えた。全文削除ボタン、SVGアイコン、短い初期表示、小さなヘッダー・サイドバー、幅を使うチャットへ変更。ライト/ダーク、VisualViewport、セーフエリア、原文・注意・出典、88件のデータ、確認質問・会話エンジンは維持する。新しいモデル設定キー以外の既存保存形式は変更しない。

## ブラウザ分離とPages

GitHub Pagesはアプリ側からHTTP応答ヘッダーを設定できない。公開済みのWASMはSharedArrayBuffer/pthreadを使うため、パラメータだけで単一スレッドにできる構成ではない。単一スレッド版を独自ビルドして未検証のSDKへ置き換える方法は採用しない。

Service Workerが扱う通常の全ナビゲーションにCOOP/COEPを付け、`voice_iso=1` へのモード変更を不要にした。Ruri Workerの分離対応と外部モデルCORSは実モデルで確認。最初のネットワーク応答にはSWがまだ作用しないため、そのページで初めてマイクを使う場合だけ1回開き直す。入力・履歴・会話文脈・選択候補をsessionStorageで一時引き継ぎ、読み込み後に削除する。実機の許可/AudioContextの制約を尊重し、この初回開き直し後はマイクをもう一度押す案内を出す。通常の次回アクセスでは追加の開き直しは不要。分離非対応、保存不可、SW準備失敗はエラーにして文字入力を残す。

Safariとホーム画面PWAは別保存領域になり得る。実機のSW更新・初回許可・AudioContext再開・キーボードは未検証であり、WebKit検証を実機検証とは扱わない。

## 実測と検証の意味

`docs/diagnostics/voice-ux-20261016/` に生の測定とUI検証結果を保持。Linux Chromium/WebKitで、短文・防災語句・否定・話し言葉の台本・41.7秒の長文を同じ合成音声で認識した。音声生成はローカルOpen JTalk/HTS Mei。生成手順・ライセンス・音声は `scripts/evaluation/synthetic-ja/`。人の自然発話、騒音、マイク収録、iPad性能の評価ではない。

| 指標 | Tiny | Base |
| --- | ---: | ---: |
| 5本の集計CER（両ブラウザで同一） | 12.05% | 16.71% |
| Chromium 新規Worker初期化 | 1.00秒 | 1.65秒 |
| WebKit 新規Worker初期化 | 2.26秒 | 2.72秒 |
| Chromium ブラウザ全プロセスRSS合算の最大サンプル | 1.09 GiB | 1.49 GiB |
| WebKit/iPadのピークメモリ | 未測定 | 未測定 |

初期化は検証済み重みをローカルHTTP経由で渡した時間であり、一般回線の初回ダウンロード時間ではない。RSSは100ms間隔のLinuxプロセス合算で共有ページを重複計上し、WASM単独のメモリでも実機Safariの値でもない。速度・1秒音声当たりの処理時間・各文の認識全文・文字誤りは生のJSONに保存。1回ずつの測定で、統計的な性能保証ではない。

無音追加前はTiny 12.60%、Base 16.71%。追加後に短い文末の一部が改善したが、長文途中の文末や同音語の誤りは残った。Baseで一部の否定表現が改善しても全体CERは悪化した。モデル由来/VADの境界による欠落は今回だけでは完全解決していない。自動語句補正で安全上重要な否定・数字を書き換えず、入力欄での確認を維持する。認識結果から安全を断定しない。

テストの `passed` は実行や状態遷移の成功であり、ASRの完全な正確性や安全認証を意味しない。

検証項目:

- 全ユニット・安全回帰（183件）、公開ビルドの88件整合性と生成AI混入検査。
- 実Tiny/Base: オンライン/保存後オフラインのload/start/stop/close、同じWorkerで録音再開、Ruriから音声へ/音声から実Ruriへ、モデル保存とブラウザ再起動後の再利用。
- Chromium/WebKitのUI状態テスト（SDKと入力音源をテストダブルに限定）：一押し準備・開始、停止時の最後の行、重複抑制、未確定末尾、手動編集保持、キャンセル、権限拒否、再試行、Base失敗からTiny、解放失敗時の軽量検索、モデル準備中のキャンセル。
- Chromium/WebKitの画面検証：iPad横/縦、phone/desktop、キーボード相当のVisualViewport縮小、スクロール、全88件の原文/出典、テーマ、辞書と会話、オフライン再起動。
- 初回分離の一時引き継ぎ、通常ナビゲーションの分離、ストレージアクセス拒否でも文字検索を継続。
- SW更新・旧タブのオフライン資産・保存済みモデル領域保持。PRのfull CIで既存の実Ruri回帰全体も実行する。

実機未検証: iPad第10世代のマイク権限・人の発話精度・長時間安定性・熱/メモリ制限・初回/再開速度・Safari/PWAの録音とバックグラウンド・OSキーボード・ストレージのOSによる削除。WebKit上の実モデル認識とUI成功だけでこれらを成功扱いしない。
