## 1. プロジェクト概要

**プロジェクト名：** bosai-ai（仮称）  
**開発方式：** 新規リポジトリでの独立開発  
**公開先：** GitHub Pages  
**対象端末：** iPad第10世代  
**対応ブラウザ：** Safari（iPadOS 26以降を想定）  
**動作方式：** PWA・端末内AI・オフライン対応

### 開発目的

従来のキーワード検索型防災辞書を、自然な日本語で質問できるAIチャットボットへ進化させる。

インターネットが利用できない災害時でも、保存済みの防災情報を検索し、分かりやすい回答を提供することを目指す。

## 2. 既存プロジェクトとの関係

参照元：`fun7772ei/bosai-app`

- 既存リポジトリは変更しない。
    
- 新規リポジトリ`bosai-ai`を作成する。
    
- 既存の`data.js`に含まれる防災辞書88項目を流用する。
    
- 既存の検索UIやCSSは引き継ぐ必要はない。
    
- 辞書データの内容、優先度、注意事項、出典を維持する。
    
- 既存アプリと新アプリは独立して運用する。
    

## 3. システム構成

### フロントエンド

- HTML5
    
- CSS3
    
- JavaScript / TypeScript
    
- チャット中心のレスポンシブUI
    
- iPad Safariへの最適化
    
- Service Workerによるオフライン動作
    

### ローカルAI

**第一候補モデル：Qwen3-0.6B**

- 4bit量子化版を使用
    
- Transformers.jsによるブラウザ内推論
    
- WebGPUによる実行を優先
    
- 思考モード無効
    
- 短い回答の生成を基本とする
    
- 外部AI APIを使用しない
    

iPad第10世代での動作は実機検証で判断する。性能やメモリ制限により利用できない場合は、軽量検索方式への切り替えを行う。

### 辞書検索

- ローカルRAG方式
    
- 防災辞書88項目を検索対象とする
    
- タイトル、概要、キーワード、手順、注意事項を利用
    
- 質問との関連度に基づいて候補を選ぶ
    
- 上位3〜5項目程度を生成AIへ渡す
    
- 当初は軽量な関連度検索を実装し、必要に応じて意味検索モデルを追加する
    

## 4. AIチャット機能

### 基本機能

ユーザーが「地震が起きたらどうすればいい？」などの自然文を入力すると、関連する辞書情報を取得し、Qwen3が回答を作成する。

回答には以下を含める。

- 質問に対する簡潔な回答
    
- 必要に応じた具体的な行動手順
    
- 参照した辞書項目
    
- 詳しい情報への導線
    
- 関連する質問候補
    

### 会話履歴

- 同一セッションでの会話の継続
    
- 直前の質問を踏まえた追質問への対応
    
- IndexedDBを利用した端末内保存
    
- 履歴削除機能
    
- 長い会話履歴による負荷を防ぐため、参照する履歴を制限
    

### AIの制約

- 防災辞書に存在しない情報を事実として生成しない。
    
- 回答の根拠となる辞書項目を表示する。
    
- 不明な場合は推測せず、情報がないことを伝える。
    
- 緊急性が高い質問では、AI生成より先に辞書の確定情報を表示する。
    
- リアルタイムの災害情報を取得できない状態を明示する。
    

## 5. オフライン対応

### PWA

- ホーム画面への追加に対応
    
- 独立したアプリ画面で起動
    
- インターネット接続なしで利用可能
    
- アプリ本体と辞書データをキャッシュ
    

### AIモデルの保存

初回オンライン時に、Qwen3モデルと必要な実行ファイルをダウンロードする。

保存対象：

- Qwen3の量子化モデル
    
- Tokenizerとモデル設定
    
- AI推論用JavaScript / WASM
    
- 防災辞書データ
    
- PWAのHTML / CSS / JavaScript
    

モデルはHugging Faceなどから配信し、端末側のCache API等に保存する。

ダウンロードの進捗表示、保存完了確認、再ダウンロード機能を実装する。

ブラウザによるストレージ削除の可能性があるため、永続保存を保証できないことを考慮する。

### フォールバック

AIが利用できない場合でも、辞書の検索と閲覧を継続できるようにする。

Service Workerの更新によって保存済みのAIモデルが意図せず削除されないように、キャッシュを適切に分離する。

## 6. UI・UX

### メイン画面

チャット画面をアプリの中心とする。

- チャット形式のメッセージ表示
    
- 画面下部の質問入力欄
    
- 送信ボタン
    
- AI生成中の状態表示
    
- 回答の途中停止
    
- 関連質問の選択
    
- 辞書の詳細表示
    

### その他の画面

**辞書画面：** 既存の88項目をカテゴリ別に検索・閲覧できる画面。

**設定画面：** AIモデルのダウンロード状態、ストレージ情報、履歴削除、モデルの再取得などを管理する。

### デザイン方針

- Material Design 3を参考にする。
    
- iPadの画面サイズを活かす。
    
- 読みやすい文字サイズと十分なタップ領域を確保する。
    
- 長いアニメーションや重い演出は避ける。
    
- オフライン状態やAI利用可否が分かるようにする。
    

## 7. 非機能要件

- iPad第10世代で安定動作すること
    
- 質問内容を外部サーバーに送信しないこと
    
- 原則として端末内で検索と生成を完結すること
    
- AI読み込み時に画面が固まらないこと
    
- AIが失敗しても辞書を利用できること
    
- Safariのタブ再読み込みやPWA再起動に対応すること
    
- モデル未保存時でも辞書は利用できること
    

## 8. 開発フェーズ

### Phase 1：AI動作検証

新規リポジトリを作成し、Qwen3-0.6Bを単独実行するテストページを実装する。

確認項目：

- Safariでモデルを読み込めるか
    
- WebGPUで推論できるか
    
- 日本語の質問に回答できるか
    
- モデルの読み込み時間
    
- 生成速度（tokens/sec）
    
- 長時間利用時の安定性
    
- 再起動・オフライン時のモデル再利用
    

### Phase 2：辞書とAIの統合

- 既存データ88項目の移植
    
- ローカル検索機能
    
- 検索結果のAIへの受け渡し
    
- 辞書に基づく回答生成
    
- 参照元表示
    

### Phase 3：チャットUIの実装

- 新規UIの作成
    
- 会話履歴
    
- 関連質問
    
- 辞書の詳細閲覧
    
- 設定画面
    

### Phase 4：オフラインPWA化

- Service Workerの実装
    
- AIモデルの保存管理
    
- 機内モードでの動作検証
    
- iPadホーム画面からの起動確認
    
- ストレージ不足とAIエラーへの対応
    

## 9. 完成条件

以下を満たすことを目標とする。

1. iPad第10世代のSafariでアプリが動く。
    
2. 自然な日本語の質問を入力できる。
    
3. 既存の防災辞書から適切な情報を取得できる。
    
4. Qwen3が辞書に基づく回答を生成できる。
    
5. 回答の根拠を確認できる。
    
6. 初回セットアップ後、機内モードでもAIが動作する。
    
7. AIが利用できない場合も辞書を検索できる。
    
8. 既存のbosai-appに変更を加えず、独立して公開できる。
    

**開発上の最優先事項：** Qwen3-0.6Bが実機で動作するかを最初に確認し、その結果に応じてAI実装を最適化すること。
