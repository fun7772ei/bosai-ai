# Ruri優先の公開ベータ版

必須対象はiPad第10世代（A14/RAM4GB）・iPadOS26.5 SafariとオフラインPWA。ただし**iPad Safari実機・ホーム画面PWAは未確認**。一般的な防災情報88件を探すベータ版であり、現在地の安全判断、リアルタイムの警報・予報・避難所開設、診断・個人の投薬量は回答しない。正式完成や防災上の安全性確認済みとは扱わない。

公開先は https://fun7772ei.github.io/bosai-ai/ 。本資料の公開前部分と、公開後の実際のActions/HTTPS検証記録を区別する。公開状態は末尾に追記する。

## 実装と公開範囲

既定は軽量検索＋Ruri-v3-30mのスコア統合。Ruri単独・モデル不要の軽量検索も選べる。Ruri未保存・IndexedDB失敗・初期化/推論失敗時は軽量検索を維持し、実際に使った検索方式と切替理由を表示する。ダウンロードは明示ボタンだけで行い、保存済みなら検索時に読み込む。外部AI APIへ入力を送信しない。

画面はMaterial Design 3を参考に、質問入力・関連候補・条件の絞り込み・モデル準備を分けた。候補を「質問の答え」と呼ばず、原文はユーザーが項目を選択してから表示する。概要・全手順・注意・準備品・出典は元88件のまま。自動生成による補足は一切しない。

公開用`index.html`の入口は`beta-main.js`→`ruri.worker.js`。研究用の`main.js`・`cpu.worker.js`・`experiment.worker.js`・wllamaの実行WASMを公開成果物へ入れない。公開workerのプロトコルは保存・読込・Embedding・解放だけで、`load-llm`等を拒否する。ビルド時の検査とブラウザでの未知メッセージ試験で確認した。Transformers.jsの依存ライブラリ内の汎用実装と、アプリが実行できるメッセージ経路は区別する。

LFM・Qwen等の研究コード・モデル選択と保存データは維持する。研究画面は`research.html`、明示的な`npm run dev:research` / `npm run build:research`で利用する。後者は`research-dist/`へ出力し、Pagesにはアップロードしない。公開画面から研究機能へ移るリンクはない。

- PR #9のcold LFM初期化中の停止：ロード中のchannelを終了し、停止状態を記録して後続生成も防ぐ。実GGUFをローカル研究画面で読み込み中に停止し、回答生成へ進まず終了することを確認した。
- 候補1件・全件同点のスコア統合：非空でスコア幅ゼロなら正規化値1を与え、検索器の重みがゼロにならないよう修正。

- 語彙「到着予定/到着予報」等を「到達予想時刻」へ検索上で展開し、津波の避難の締切を第1波後の行動と取り違える問題を改善。原文は変更していない。

## 範囲判定と精度評価

検索の前に、現在の予報・連絡先・個別の薬の量・未収録分野などの明示的な範囲判定を行う。曖昧な質問は状況選択を促す。明示された津波と洪水の検索候補を相互の代用品にしないよう絞る。**Ruriの類似度を「答えがある確率」と解釈しない。** 範囲判定はルールであり、未知の言い回しを完全に判別するものではない。

旧40問とPR #9の旧64問は開発・回帰用。コミット`87cf7c3`で検索・範囲判定・統合を固定し、その後に[未使用80問](../scripts/evaluation/beta-unseen-80.json)を作成した。[freeze](diagnostics/beta-evaluation-freeze.json)と[作成来歴](diagnostics/beta-unseen-provenance.json)を保持する。最終正解を見た検索・閾値・範囲ルールの調整は行っていない。後から加えた全質問共通の医療に関する注意書きと試験ハーネス強化は、検索結果を変更しない。

正解ラベルは元データを読む手作りで、独立した防災専門家の評価ではない。正解あり52（通常16・言い換え16・危険12・複数情報8）、未収録20、曖昧8。関連集合は網羅的とは限らない。Top-3/5は少なくとも1正解を含む率であり、必要な情報の全網羅率とは異なる。

| 未使用80問の方式 | Top-1 / 52 | Top-3 / 52 | Top-5 / 52 | 明示的な未収録棄却 / 20 | 候補なし / 20 | 曖昧の絞り込み / 8 |
|---|---:|---:|---:|---:|---:|---:|
| 軽量 | 43（82.7%） | 49（94.2%） | 49（94.2%） | 14 | 14 | 5 |
| Ruri単独 | 48（92.3%） | 51（98.1%） | 52（100%） | 14 | 15 | 5 |
| 併用・既定 | 48（92.3%） | 52（100%） | 52（100%） | 14 | 14 | 5 |

全方式で正解あり52問の範囲判定による棄却0、危険12問の期待Top-1不一致0。複数情報8問に必要な項目をすべてTop-5へ含めたのは、軽量5・Ruri7・併用7問。これらは今回の問題セット上の値で、安全性の保証ではない。

旧64問では、旧併用の未収録誤提示7/8に対して、今回の明示棄却8/8。危険14問のTop-1不一致は旧併用1→今回0。旧64問のTop-1は今回51/56で、旧52/56より1件少ない。曖昧4問を強制的なAI検索から状況確認へ変えたため、比較の分母を明記する。明確な正解あり52問の併用Top-1は旧・新とも50/52。精度全般が改善したとまとめず、危険な取り違えと未収録の扱いの改善として評価する。

成功例は、揺れ中の台所・エレベーター・到達予想時刻の意味、津波注意報での海上レジャー、停電時の節電/冷蔵庫など。検索後も条件・注意を自分で確認する。

未使用問題で未収録棄却を取りこぼしたのは以下の6件：

- 避難所Wi-Fiの「合言葉」
- 「インスリンを3単位追加してよいか」という数値を提示した問い
- 煮沸に必要な分数
- 透析の送迎先の具体的病院名
- 必要カロリーの計算
- 固定金具の販売店

いずれも関連候補を返しても、その具体情報は原文にない。特に投薬判断ができると解釈してはいけない。個人の診断・薬量を判断しない注意を常時表示し、候補は自動で回答表示しない。曖昧3問も状況確認を十分に促せなかった。最終問題を使った追加調整は行わず、次の改善には別の評価問題を用意する。

[全実測・集計](diagnostics/beta-summary.json)、[未使用80問の実ブラウザ記録](diagnostics/beta-final-80.json)、[旧64問の回帰](diagnostics/beta-regression-64.json)。同じ質問を3方式で操作し、実Ruriを使って評価した。疑似Embeddingではない。

## 保存容量・速度・メモリ

Ruriは既存の固定revision・ONNX q8、256次元。重み37,048,575 bytes、Tokenizer/設定込み**43,778,410 bytes（43.8MB）**。アプリ・ORT WASM・辞書・事前計算ベクトルのshell cacheは別に約28MB。モデル本体をGitへ含めない。88件の文書ベクトルは実モデルで事前計算済みで、端末では質問だけを計算する。

| 未使用の正解あり52問 | 合計中央値 | 質問Embedding中央値 |
|---|---:|---:|
| 軽量 | 0.7ms | 実行なし |
| Ruri単独 | 20.0ms | 18.7ms |
| 併用 | 20.3ms | 18.9ms |

初期化は再読込/再試行の実問で約1.90〜1.96秒、初期化を含む検索完了は約2.07〜2.23秒。上表はモデル常駐後。軽量を選んでも、すでにロードしたRuriは明示解放するまで保持する。時間はcontrollerの段階計測で、画面paintまでの測定ではない。モデル取得のネットワーク時間は含まない。

Linux Chromium全子プロセスのPSSピークは最終80問試験で約812MiB、旧64問回帰で約819MiB。解放前→3秒後は678→369MiB、別回帰では824→379MiB。Workerハンドルだけでなく実際のPSS低下も観測したが、全回収・長期リークなしの証明ではない。500ms採取で瞬間ピークを取り逃がす可能性がある。Chromiumの数値をiPad Safariの必要メモリ・速度へ換算しない。

保存は同じIndexedDB `bosai-ai-model-chunks-v1`・4MiB分割・全分割後の完了情報。保存済みの同じURLは再取得せず、不足分だけを明示保存する。旧GGUF等・旧モデル選択は変更しない。モデル更新でも保存を自動削除しない。アプリの更新ではshell cacheだけを更新し、モデル保存を消さない。旧タブは閉じて新しい版を開く。アプリやサイトデータの削除は不要。

## 検証・再現

Node24.19.0/npm11.9.0。単体75件、本番build、公開artifact検査、元88件の全フィールド/ID/順序/blob整合性が成功。ChromiumでWebGPUを無効化してCPU/WASMを使用した。

実Ruriのブラウザ試験では未使用80×3=240、旧64×3=192ケースに加えて以下を確認：

- 保存通信を1回意図的に失敗→軽量検索を維持→不足分再試行。
- 読み込み中の停止→再初期化、推論失敗後の軽量切替、モデル再利用、解放。
- 原文/注意/出典の完全表示と候補選択、曖昧な状況の選択。
- 公開workerへ研究用メッセージを送っても拒否。
- 実モデルが常駐したままSW更新を待機→旧画面の検索維持→全ブラウザ終了→オフラインで新shell起動→保存Ruri再利用。
- 旧モデル保存のダミーsentinel・旧選択値の維持。sentinelは互換確認用で、旧モデルの実推論成功とは扱わない。
- 390px/1024pxで横はみ出しなし。スクリーンショットは画面レイアウトの確認で、iPad Safari実機ではない。
- 研究用cold LFM停止は別のローカル経路で実GGUFを使用し、生成へ進まないことを確認。

```bash
npm ci
npm test
npm run build
node scripts/check-public-build.mjs
npx playwright install --with-deps chromium
python3 scripts/fetch-ruri-assets.py
npm run preview -- --port 4173 --strictPort
# 別ターミナル
node scripts/beta-browser-check.mjs --cases=scripts/evaluation/final-64.json --tag=beta-regression-64
node scripts/beta-browser-check.mjs --cases=scripts/evaluation/beta-unseen-80.json --tag=beta-final-80
node scripts/summarize-beta.mjs
```

ローカルの`--with-deps`はsu認証制約があるため、既存Chromiumを使用した。GitHub CIでは依存導入も含めて別に確認する。最終問題の再作成/上書きや最終結果を見た調整はしない。公開検証は`node scripts/pages-beta-check.mjs`で実HF取得・IDB SHA256・HTTPS/WASM・88件・保存再利用・オフラインbrowser再起動を検査する。これは公開後に実施し、以下へ記録する。

## iPad Safariでの最小確認

1. オンラインで旧bosaiのタブを閉じて開き直し、「ぼうさい辞書AI」「ベータ版」を確認。保存やPWAアプリを消さない。
2. モデル未保存なら軽量検索で「寝ているときに地震が来たら？」を1問。候補をタップし、原文・注意・出典を見る。
3. Ruri約44MBだけを明示保存。読み込み中の停止→再試行を1回行う。
4. 併用で「高台に間に合わない津波」「避難所で断水したトイレ」等、異なる3問。曖昧な「水のことで困る」は条件を追加する。
5. Safariを再読み込みし、保存済み表示と再取得なしを確認。安定したら機内モードで1問。
6. ホーム画面PWAは別に保存状態を確認し、機内モードの再起動後に1問。通常タブでの成功をPWAの成功としない。

診断JSONのuserAgent・standalone・build・保存状態・所要時間を添える。Safari終了/リロードが起きても、保存済み重みが削除されたとは断定しない。
