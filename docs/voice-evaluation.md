# Japanese voice regression harness (2026-10-15)

Versioned cases: scripts/evaluation/voice-ja-cases.json (28 hand-written utterances). This is an evaluation *script*, not recordings and not a model accuracy claim. Read each reference naturally on the same iPad, with matched microphone/distance and environment for Tiny/Base; keep the audio recording IDs external/private as appropriate.

1. Capture actual FINAL onLine recognized text (not provisional onText) with exact case IDs for each model in a JSON file:
   {"model":"tiny","results":[{"id":"v01","transcript":"..."}]}
2. Run: node scripts/voice-cer.mjs --model tiny --input tiny-capture.json --output test-results/voice-tiny.json
3. Repeat with model=base using separate file/output. Empty/missing cases remain unmeasured with null CER. Empty transcript is a valid measured failure only if an actual attempt was made and explicitly recorded.
4. CER is Levenshtein distance (substitute/insert/delete) divided by reference Unicode code point length, micro-aggregated across MEASURED cases only. NFKC + lowercase + remove Unicode spaces, punctuation and symbols are applied to both transcript/reference. Scores may exceed 100% for long insertions. Numerical kanji vs digits are not normalized except NFKC; consistent with documentation, but inspect rows when analyzing false alarms.
5. Compare the same case IDs across models, count skipped cases, and separately note failures to load, stop, memory pressure, download bytes, offline reload and processing time. Do not compare a Tiny 28-case partial run to a full Base run as equivalent.

No recordings/transcriptions/measurement results have been generated by this preparatory PR. Expected high-impact error classes: earthquake vs confidence, tsunami negation, flood road vs vehicle, alert level numbers and long queries. Keep user confirmation mandatory before real search.
