## 修正内容

### P1：未対応の質問から古い文脈へ戻る

`forget()` で話題・状況・構造化条件・候補・選択原文・確認状態をまとめて解除する。早期の `coverage()` 棄却と、実検索後の `scope.kind=unsupported` の両方へ適用した。未対応の津波警報質問の後に「そのとき」と言われても、前の地震場面も、答えられなかった警報質問も引き継がず確認する。

### P2：聞き返しで古い候補が有効なまま残る

すべての確認質問は `clarify()` を経由して候補・参照先を無効化する。条件への回答待ちの場合だけ、未確定の状況を保持し、原文の選択は解除する。複数人、複数災害、文脈超過、原文未選択の詳細要求も対象。選択トークンを質問単位で発行し、同じ原文IDが後の検索に再登場しても古いボタンは使えない。過去の確認選択肢・詳細ボタンも現在のターン以外では無効にする。

### 構造化条件と原文の用途

`conversation-context.js` は、災害/道路/冠水の真偽/移動手段/車内への浸水/高台への到達制約/履物という目的を小さなスキーマで保持する。

- 「大雨」だけから冠水は推測しない。移動の質問で冠水の有無が不明なら確認する。
- 「車ではなく徒歩」の訂正で移動手段だけを更新し、確認済みの道路・冠水を保持する。否定した車内浸水は残さない。
- 「車を置いて/車から降りて歩く」は現在の徒歩移動として扱う。徒歩と車の二人がいる場面とは分ける。
- 複数の主体は確認する。家族呼称の限定語彙を使うもので、あらゆる主体/否定構文を解析できるわけではない。
- 検索入力へ有効な条件を補う。200文字を超えれば切り捨てず確認する。モデル・Tokenizer・Embeddingは変更していない。

`conversation-evidence.js` は、確認できた条件と5種類の原文用途（冠水歩行/冠水路への車進入/水没車脱出/津波の高台へ間に合わない/浸水時の履物）を照合する。原文タイトルをキーとする小さな文書用途表であり、評価質問の全文・IDによる分岐や固定回答ではない。原文は変更せず、全手順・注意・出典を表示する。

**Ruriだけの順位変更ではない。** 文脈から再構成した質問で実Ruri検索を行い、用途が対応する原文を優先する。必要な原文がRuriの上位5件にない場合は、文書用途表から候補として追加できる。この場合 `provenance=catalog-capability`、`score=null` と明示し、架空のEmbedding類似度を作らない。今回の最終18正解あり質問では、補完後の検索だけで17/18がTop-1、用途による順位付け後が18/18だった。Ruriモデル自体の性能向上を示す数値ではない。

原文用途の明らかな相違や、洪水歩行に対する津波/竜巻/車/履物などの代用候補を除き、用途不明の関連候補は残す。「状況・行動の条件に対応／適用は未確認」と「関連情報・この質問への適用は未確認」を区別する。**用途対応も、質問への十分性や現在の安全性を認証しない。** 自由生成なし、原文の自動回答化もしない。

PR #14の研究ガードは丸ごと取り込まない。通常検索のスコア・閾値・モデル保存・Worker・DB・SWは変更していない。
