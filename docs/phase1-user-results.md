## 判断と変更

LFMは実際の初期化・短文10回完了の記録があり、Qwenの初期化時クラッシュ報告とGemmaの連続生成中クラッシュ報告に比べ、現時点の第一候補として妥当。LFMを第一候補として仮採用するが、最終採用・Phase 1全面成立・完全オフライン完成とは扱わない。Phase 2へは進まない。

新規利用の初期選択だけをLFMへ変更。既存の明示モデル選択と旧Qwen形式設定は保持し、Gemma・Qwenの比較選択と全保存データを残す。Qwenの既存URLと互換性用ヘルパーの既定モデルは維持。画面にモデル別のユーザー実機報告と未確認範囲を表示する。今回のアプリ版は `7ca23c3c9e36`。

次はLFMで異なる短い入力・与えた文章の要約を試し、生成内容を評価する。その後、タブ終了→機内モード＋Wi-Fiオフ→再起動→保存済みだけで初期化・短い生成を確認。ここが成立してから停止・復旧・長時間を確認する。Gemmaのクラッシュを繰り返す必要はない。保存削除も不要。

開発側ではNode.jsの33テストと本番ビルドが成功。新規LFM選択、旧Qwen移行、既存の明示選択保持を回帰検証。ブラウザ検証の初回は前ターンのpreviewが終了しており接続拒否で失敗したが、port 4173でpreviewを再起動後に成功した。新規LFM選択、各候補の外部重み・形式復元・オフライン再利用・Qwen保持・モデル別診断・アプリ更新を確認し、未処理pageerrorはなし。保存テストは引き続きダミーデータであり、今回のユーザー提供実モデル生成ログとは区別する。このCloudのWebGPUはshader-f16非対応のため、開発側で実モデルのq4f16推論は実施していない。
