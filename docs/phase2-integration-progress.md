## 実装済み

1. `src/conversation-applicability.json` に88原文IDすべてのsidecarを追加。原文title/category/レコード全フィールドの32bitフィンガープリント、場面、対象行動（86件の粗分類・2件未分類）、対象者（原文題名・要約に明確なものだけ）、前提条件、答えの一般的種類、原文だけでは答えられない内容を記録。現状は**title/summaryからの暫定注釈であり88件の専門家による意味監査ではない**。詳細な前提条件を証明した4件（ID 2,69,70,71）以外へは未根拠の条件を強制しない。追加機能では常に原文・全手順・注意・出典を参照し、原文JSONは不変。
2. `src/conversation-applicability.js` で一対一ID・原文一致・証拠文字列・型を確認。不整合があれば適用候補判定を行わず `needs-confirmation` に落とす。質問の事実が前提と矛盾すれば `not-applicable`、未知なら `needs-confirmation`、明確なfocusと確認済み前提が揃うときだけ `candidate` にする。**候補＝その質問への十分な答え、ではない。** 会話の候補UI/診断に3状態を追加。適用状態は現状ラベル表示中心で、関連候補の全文が条件に合うかの包括的な判定は未完成。
3. `src/question-intent.js` で「特定災害の発生日時／予測日時」および「特定道路の現在の安全性」への回答不能判定を定義。会話前段の `coverage` から呼び出す。**通常辞書検索の凍結された `src/query-scope.js` は元に戻した。** 通常検索は検索結果としてしか扱わず、現在の安全性の回答とは表示しない。
4. `src/voice-draft.js` でMoonshine `onText` 暫定結果と `onLine` 確定結果（64bit不透明string ID）を別に保持。同一IDの更新は置換。録音停止時に最後の暫定テキストを消さず、確認が必要なことを表示する。自動送信なし。マイク準備・録音は既存 `MicTranscriber` のみ。
5. `src/beta-main.js` の音声入力を現在の入力欄（従来検索または会話）へ接続。認識途中も表示し、ユーザーが編集中なら後続イベントで上書きしない。最大120件のイベント種別・長さ・時刻だけの診断（発話本文を含めない）を明示エクスポートのJSONに追加。UIは `src/conversation-ui.js` の会話モードへ従来音声操作要素そのものを移動し、独立した音声エンジンを追加していない。音声モデルとRuriを同時常駐させない既存処理を維持。
6. 会話候補の原文を全文表示する既存の仕組み、Service Worker、Ruri IndexedDB、公開mainへの変更なし。チャット入力はタッチ領域・画面高・下部コンポーザー・末尾スクロールを改良。
