# iPad Safari / PWA 実機検証（未実施、2026-10-15）

対象はPR #21のブランチから作成した `dist`。main / 現在の公開Pagesはこの変更の検証対象ではない。公開せず、証明書をiPadが信頼するHTTPS検証環境で `/bosai-ai/` を配信する。Safari / iPadOS / 機種 / ビルドID / 空き容量 / Wi-Fi環境 / マイク距離を記録する。既存の本番オリジンのサイトデータを削除しない。別の検証オリジンを使う場合、保存済み本番モデルの引き継ぎを検証したとは扱わない。

1. **既存データの維持**：同じ検証オリジンで旧ビルドにRuriを保存し、検索できることを確認。旧タブを残して新ビルドを配信し、旧タブの検索・原文表示が続くことを確認。その後全タブを閉じて再起動。期待：Ruri保存済み表示を保ち、再ダウンロードせず検索できる。消去・再保存で代用しない。
2. **文字・原文**：音声を準備せず、辞書・会話・設定を往復。全88件一覧から原文を選び、手順・注意事項・出典リンクを確認。機内モードで再起動し、軽量検索と一覧が使える。期待：現在の警報、道路の現在安全性、個別投薬量を回答しない。画面幅・横向き・ソフトキーボードで横はみ出しや操作不能がない。
3. **Tinyの準備**：オンラインで音声実験モードを開く。必要なら全タブを閉じ、`?voice_iso=1` を再度開く。利用条件を確認して準備。期待：初回だけSDK・モデル取得の通信と進捗を表示。Ruri実行中は待ち、読み込み済みRuriは解放する。TinyStreamingを取得しない。
4. **マイクと確認**：直接「マイク開始」をタップし許可。`自信が発生した。津波は来ない。震度5。` に相当する認識を得たら、暫定・確定の別表示、停止後の補正候補を確認（誤認識が出ない場合は補正の実ASR試験を未実施とする）。期待：自動補正・自動送信しない。採用は明示ボタンのみ。否定・数値・主体を維持。録音中の手修正を次のコールバックで上書きしない。暫定末尾・手修正ありでは補正候補を出さない。
5. **評価28文**：「音声評価」を開きv01を選ぶ。毎回新しい録音を開始し、1ケースを読み、停止して「直前の試行を記録」。全28件を同条件で実施してTiny JSONを書き出す。期待：未試行は未記録。同じ録音を複数ケースへ転用できない。書き出しは補正前のonLine原文のみ。無音も実際に試行後なら失敗として記録可能。暫定末尾の有無も残る。評価画面の入力・記録は再読み込みで消えるので先に書き出す。
6. **Baseの任意評価**：Tiny記録の書き出し後、「Tiny / Base の実機比較について」からBase評価画面を開く（`?voice_iso=1&voice_eval=base`）。期待：iPad未検証・評価専用の表示が出る。自動取得しない。準備ボタン後のみBaseを取得する。Tinyと同じ28文・環境・距離で反復しBase JSONを書き出す。読み込み不能・タブ終了・音声欠落・発熱なども記録し、CER比較できたと扱わない。
7. **停止・往復**：録音停止でマイク使用表示が消えること、音声モデル解放後にRuri検索が再開することをTiny/Baseそれぞれ確認。マイク拒否、バックグラウンド移動、ページ離脱、再開も試す。期待：マイク開始失敗後も文字入力が使える。録音内容は外部送信されない。保存済みRuri/音声モデルを削除せず、同時に推論モデルを使わない。SDKのclose呼出しはOSの即時メモリ返却の保証ではない。OSによるタブ終了・メモリ警告は別記する。
8. **完全オフライン**：各モデルをオンラインで一度開始・停止した後、全タブを閉じて機内モードへ。Safariとホーム画面PWAの両方で通常画面、Tiny評価画面、Base評価画面を起動。期待：アプリ・辞書、保存済みRuri、準備済み音声SDK・モデルを再利用し、新規外部要求なしで開始・停止・Ruriへの往復ができる。Safari/PWAの保存領域差は実測し、未保存モデルの準備失敗時も文字入力は使える。
